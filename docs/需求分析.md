## 1. 项目背景与目标

### 1.1 项目背景

本项目为某高校校庆活动配套建设的纪念品认购私域微信小程序。学校在校庆期间将推出一系列限量纪念品，面向国内及海外校友开放认购。为满足不同地区校友的使用习惯与支付需求，需构建一套完整的线上认购平台，涵盖商品展示、校友身份核验、订单管理、多货币支付、物流跟踪及售后服务等核心功能。

项目背景要点：
- 面向校庆纪念品的限时认购场景，具有活动期集中访问、用户身份敏感的特点。
- 用户群体覆盖国内外校友，支付渠道需兼顾微信支付（国内）与 PayPal（海外）。
- 平台采用私域运营模式，依托微信生态（微信登录、小程序、订阅消息）触达用户。
- 校友身份核验为本平台的核心安全机制，初期采用人工审核，并为后续对接校友系统预留 API 接口。

### 1.2 项目目标

| 目标维度 | 具体描述 |
|---------|---------|
| 服务目标 | 为国内及海外校友提供便捷的纪念品认购渠道，提升校庆活动参与感与用户体验 |
| 业务目标 | 实现纪念品在线认购、支付、物流全流程数字化管理，降低人工运营成本 |
| 支付目标 | 支持微信支付（国内校友）与 PayPal（海外校友）双通道，覆盖全球校友群体 |
| 管理目标 | 提供完善的运营管理后台，支持商品、订单、校友、数据统计等全维度管理 |
| 扩展目标 | 预留校友系统 API 对接接口，支持未来阶段与学校官方校友数据库集成 |
| 合规目标 | 符合微信小程序平台规范、PayPal 合规要求及数据隐私保护相关法规 |

## 2. 用户角色定义

### 2.1 角色概览

本系统共定义四类用户角色，权限层级由低至高依次为：国内校友、海外校友、运营管理员、超级管理员。

### 2.2 角色详细说明

#### 2.2.1 国内校友（Domestic Alumni）

| 属性 | 说明 |
|------|------|
| 定义 | 已通过身份核验的国内校友用户 |
| 登录方式 | 微信一键登录（OpenID 绑定） |
| 支付方式 | 微信支付（人民币结算） |
| 核验方式 | 提交校友信息及证明材料，经运营管理员人工审核通过后激活认购权限 |
| 可用功能 | 浏览商品、提交认购订单、微信支付、查看物流、申请售后、定制刻字、提交评价、接收消息通知 |
| 语言 | 中文 |

#### 2.2.2 海外校友（Overseas Alumni）

| 属性 | 说明 |
|------|------|
| 定义 | 已通过身份核验的海外校友用户 |
| 登录方式 | 微信一键登录（OpenID 绑定） |
| 支付方式 | PayPal（外币结算，支持汇率换算） |
| 核验方式 | 提交校友信息及证明材料，经运营管理员人工审核通过后激活认购权限 |
| 可用功能 | 浏览商品、提交认购订单、PayPal 支付、查看物流（国际物流）、申请售后、定制刻字、提交评价、接收消息通知 |
| 语言 | 中文 / 英文双语支持 |

#### 2.2.3 运营管理员（Operations Admin）

| 属性 | 说明 |
|------|------|
| 定义 | 负责日常运营管理的后台操作人员 |
| 登录方式 | 账号密码登录（管理后台） |
| 核心职责 | 校友审核、商品管理、订单处理、物流售后跟进、数据查询 |
| 权限范围 | 拥有商品、订单、校友、物流售后、数据统计等模块的读写权限；不可管理系统级配置及其他管理员账号 |

#### 2.2.4 超级管理员（Super Admin）

| 属性 | 说明 |
|------|------|
| 定义 | 拥有系统全部权限的最高级别管理员 |
| 登录方式 | 账号密码登录（管理后台） |
| 核心职责 | 系统配置、权限管理、账号管理、支付渠道配置、数据报表设置 |
| 权限范围 | 拥有所有模块的全量读写权限，包括创建/删除运营管理员账号、配置 PayPal 账户、设置汇率策略、配置定时报表邮件等 |

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 |
|------|------|
| 页面首屏加载时间 | 小程序首屏加载时间 < 3 秒（4G 网络环境） |
| API 响应时间 | 后端 API 接口平均响应时间 < 500ms（P99 < 1500ms） |
| 并发用户支持 | 系统需支持峰值 500 名并发用户同时访问与下单，不出现明显性能降级 |
| 图片加载 | 商品图片使用 CDN 加速，列表页图片进行压缩处理，加载时间 < 2 秒 |
| 支付成功率 | 微信支付成功率 ≥ 99%，PayPal 支付成功率 ≥ 95%（依赖 PayPal 平台稳定性） |

### 4.2 安全需求

| 安全维度 | 具体要求 |
|---------|---------|
| 身份认证 | 小程序端通过微信 OpenID + JWT Token 进行会话管理，Token 有效期 7 天，刷新机制自动续期 |
| 传输安全 | 所有 API 通信强制使用 HTTPS（TLS 1.2+），禁止 HTTP 明文传输 |
| 数据加密 | 用户敏感信息（手机号、身份证号等）在数据库中加密存储（AES-256） |
| 防注入 | 所有数据库操作使用参数化查询，防止 SQL 注入攻击；输入内容进行严格校验与转义，防止 XSS 攻击 |
| 支付安全 | 微信支付回调和 PayPal Webhook 必须进行签名验证，防止伪造支付通知 |
| 接口鉴权 | 管理后台 API 必须携带有效 JWT Token 且通过角色权限校验，防止越权访问 |
| 敏感操作防护 | 关键操作（退款、删除、权限变更）需进行二次确认，并记录操作日志 |

### 4.3 合规需求

| 合规维度 | 具体要求 |
|---------|---------|
| 微信小程序合规 | 遵守微信小程序开发规范与审核标准，不使用违禁 API，内容符合微信平台要求 |
| 微信支付合规 | 按照微信支付商户规范接入，保留完整支付流水，符合金融监管要求 |
| PayPal 合规 | 遵守 PayPal 商户协议，正确处理 Webhook 事件，符合 PayPal 跨境支付合规要求 |
| 数据隐私保护 | 遵守《个人信息保护法》，小程序须提供隐私协议，明确说明数据收集范围与用途，用户有权申请删除个人数据 |
| 海外用户合规 | 针对海外校友用户，需考虑 GDPR 等国际数据保护法规的适用性 |

### 4.4 稳定性与可用性需求

| 指标 | 要求 |
|------|------|
| 系统可用性 | SLA ≥ 99.9%（月度不可用时间 ≤ 43 分钟） |
| 数据备份 | 数据库每日全量备份，保留最近 30 天备份，备份文件存储至独立存储介质 |
| 故障恢复 | 核心服务（支付、订单）具备故障自动重试机制，最大重试 3 次 |
| 监控告警 | 部署服务器资源、API 响应时间、错误率监控，关键指标超阈值时自动告警至运维负责人 |
| 灾难恢复 | RTO（恢复时间目标）≤ 2 小时，RPO（恢复点目标）≤ 24 小时 |

### 4.5 可维护性需求

- 代码需有完善的注释与接口文档（OpenAPI / Swagger 格式）
- 部署采用容器化方案（Docker），支持快速扩缩容
- 日志系统统一采集，区分错误日志与访问日志，日志保留 90 天
- 系统配置参数（如超时时间、限购数量等）可通过管理后台动态调整，无需重新部署

## 5. 约束与假设

### 5.1 技术约束

| 约束项 | 说明 |
|-------|------|
| 小程序平台 | 仅支持微信小程序，不支持支付宝小程序、百度小程序或 H5 页面 |
| 微信审核 | 所有功能须通过微信小程序平台审核，设计时须避免违反微信平台规范的功能 |
| PayPal 支付 | 海外支付仅支持 PayPal，不支持 Stripe、信用卡直连等其他外币支付渠道 |
| 微信支付 | 国内支付仅支持微信支付，不支持支付宝等其他国内支付渠道 |
| 后台访问 | 管理后台为 Web 端应用，通过浏览器访问，不开发独立客户端 |

### 5.2 业务约束

| 约束项 | 说明 |
|-------|------|
| 认购资格 | 仅通过校友认证的用户方可进行商品认购，未认证用户仅可浏览商品 |
| 活动时限 | 认购活动有明确的开始与结束时间，活动结束后自动关闭认购入口 |
| 刻字商品 | 含定制刻字的订单不支持退货退款（因属于定制商品），需在购买前明确告知 |
| 限量商品 | 部分纪念品为限量发行，库存消耗完毕后不补货，系统需实时准确反映库存状态 |

### 5.3 假设条件

| 假设项 | 说明 |
|-------|------|
| 校友系统集成 | 学校官方校友数据库 API 接口暂不具备对接条件，本期采用人工审核方式，系统预留标准化对接接口供后续集成 |
| 双语支持 | 海外校友界面提供中英文双语支持，翻译内容由运营团队提供；刻字内容本身不做语言限制 |
| 物流集成 | 国内物流轨迹对接第三方快递查询平台（如快递鸟），国际物流轨迹根据快递公司提供的接口评估集成 |
| 汇率数据 | 初期采用管理员手动配置汇率方式，后续可根据需要对接第三方汇率 API |
| 服务器资源 | 项目部署于云服务器（阿里云或腾讯云），具体配置根据实际并发量评估 |
| 邮件服务 | 数据报表邮件功能对接第三方邮件服务（如阿里云邮件推送或 SendGrid），邮件账号及配置由运营团队提供 |
