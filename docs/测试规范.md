## 1. 测试策略

### 1.1 测试层次

| 测试层次 | 说明 | 覆盖目标 |
|---------|------|---------|
| **单元测试 (Unit Test)** | 对 Service 层函数、工具函数进行隔离测试，使用 Mock 隔离外部依赖 | 代码行覆盖率 > 80% |
| **集成测试 (Integration Test)** | 对 API 端点结合真实测试数据库进行验证，覆盖完整请求-响应链路 | 所有 API 端点 100% 覆盖 |
| **E2E测试 (End-to-End Test)** | 在微信开发者工具模拟器中还原完整用户操作路径，验证前后端协同 | 覆盖所有 P0 用户旅程 |
| **性能测试 (Performance Test)** | 对核心 API 进行负载测试，验证并发能力与响应时间 | 500 并发，P95 < 500ms |
| **安全测试 (Security Test)** | 验证认证鉴权机制、注入防护、支付签名验证等安全要求 | 通过 OWASP Top 10 检查 |

### 1.2 测试工具

| 测试类型 | 工具 | 说明 |
|---------|------|------|
| 单元测试 | Jest (Node.js) / JUnit (Java) | 根据后端技术栈选择；使用 sinon/mockito 进行 Mock |
| API 测试 | Postman / Newman | 编写 Collection，通过 Newman 在 CI 流水线中自动运行 |
| E2E 测试 | 微信开发者工具自动化（miniprogram-automator） | 覆盖主要用户旅程，集成至 CI |
| 性能测试 | Apache JMeter / k6 | JMeter 用于场景编排；k6 用于代码化性能脚本 |
| 安全测试 | OWASP ZAP | 主动扫描 + 手动渗透测试辅助 |
| 代码覆盖率 | Istanbul (nyc) / JaCoCo | 与 CI 集成，覆盖率不达标时阻断合并 |

### 1.3 测试环境

| 环境名称 | 说明 | 数据库 | 微信支付 | PayPal |
|---------|------|--------|---------|--------|
| **开发环境** | 开发人员本地，独立数据库，自行维护 | 本地 MySQL | 沙箱模式 | 沙箱模式 |
| **测试环境** | 共享测试服务器，专用测试数据库，每日清理数据 | 测试 MySQL | 沙箱模式 | 沙箱模式 |
| **预发环境** | 与生产等配置镜像，做上线前最终验证 | 预发 MySQL（生产结构同步） | 沙箱模式 | 沙箱模式 |
| **生产环境** | 真实用户环境，先以沙箱模式验证再切换正式 | 生产 MySQL | 正式 / 沙箱分阶段 | 正式 |

### 1.4 测试优先级定义

| 优先级 | 说明 | 典型场景 |
|-------|------|---------|
| **P0（阻塞）** | 核心业务必须 100% 通过，否则阻断上线 | 登录、下单、支付、退款 |
| **P1（高）** | 重要功能，目标通过率 95% | 刻字定制、评价、物流通知 |
| **P2（中）** | 增值功能，目标通过率 90% | 报表、邮件、权限细节 |
| **P3（低）** | 优化项，可延期修复 | 界面细节、提示文案 |

## 6. 验收标准

### 6.1 功能验收

| 优先级 | 通过率要求 | 说明 |
|-------|----------|------|
| P0（阻塞） | 100% | 所有 P0 测试用例必须全部通过，任何 P0 失败均阻断上线 |
| P1（高） | ≥ 95% | 允许最多 5% 的 P1 用例存在已知问题，但需记录修复计划 |
| P2（中） | ≥ 90% | 允许最多 10% 的 P2 用例存在已知问题 |
| P3（低） | ≥ 80% | 优化类问题，可在后续版本迭代中修复 |

**关键业务零缺陷要求：**
- 下单流程（REQ-031 ~ REQ-038）：零 P0 缺陷
- 微信支付流程（REQ-041 ~ REQ-043）：零 P0 缺陷
- PayPal 支付流程（REQ-044 ~ REQ-048）：零 P0 缺陷
- 退款流程（REQ-114 ~ REQ-117）：零 P0 缺陷

**Bug 严重度分类：**

| 严重度 | 定义 | 修复时限 |
|-------|------|---------|
| Blocker | 阻断核心业务流程，无 workaround | 24 小时内修复 |
| Critical | 功能严重缺陷，有 workaround | 48 小时内修复 |
| Major | 功能缺陷，影响用户体验 | 当前迭代内修复 |
| Minor | 轻微缺陷或 UI 问题 | 下个迭代修复 |
